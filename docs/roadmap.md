| 단계 | ChatKHU로 할 일 | 남는 증빙 |

| 문제정의 | 베이즈 채팅과 Deep Research로 취준생의 고민을 조사하고 문제 문장과 페르소나를 정리 | 대화 공유 링크, `docs/problem.md` |

| 기획설계 | 시안 4장 기준 화면 흐름·데이터 모델·이벤트 규약 검토, 스튜디오 챗봇 지시문 4개와 구조화 출력 지시문 6개 | `docs/decisions.md`, `docs/prompts.md`, `design/copy.md` |
| 제작 | 스튜디오에서 챗봇 4개(직무 탐색, 경험 인터뷰, 자소서, 면접관) 생성, "API로 이 챗봇 호출하기" 켜기, API 키 발급 | 스튜디오 캡처, 챗봇 id(환경변수) |
| 개발 | 앱이 ChatKHU를 호출(대화 4종은 챗봇 엔드포인트, 추출·초안·채점·분석 6종은 chat/completions JSON 스키마, 음성은 STT·TTS). Baze CLI로 게이트웨이 키를 써서 Claude Code나 Codex를 돌리면 개발 사용량도 ChatKHU에 남음 | `server/lib/chatkhu.ts`, `api/*`, 사용량 로그 |
| 테스트 | 테스트 페르소나 대화를 모듈별 5개씩 생성해 돌리고 추출 JSON 통과율과 호출당 크레딧 측정 | `docs/test-log.md`, `/v1/gateway/usage/` 캡처 |
| 개선 | 실패 대화를 지시문에 반영하고 이력 기록 | `docs/prompts.md` 변경 이력 |
| 최종결과물 | PWA가 ChatKHU 위에서 동작, 발표 슬라이드는 베이즈 프레젠테이션, 시연은 체험 모드로 네트워크 없이 재생 | 배포 URL, 영상, 서식4 |

## 작업 넘겨받는 법

1. `CLAUDE.md`와 `AGENTS.md`를 읽습니다. 화면 문구는 `design/copy.md`, 시안은 `design/0*.png`입니다.
2. `.env.example`을 `.env.local`로 복사합니다. 키가 없어도 체험 모드로 돌아갑니다.
3. `pnpm install` 뒤 `pnpm dev`로 띄우고, 처음 열면 닉네임 화면부터 모듈 4개를 한 번씩 끝까지 넘겨 봅니다. 프로필 > 설정 > "데이터 모두 지우고 처음부터"로 초기화할 수 있습니다.
4. GitHub 이슈 "작업" 양식으로 할 일을 적고(라벨 `ai-ready`), 브랜치를 만듭니다. PR을 열면 `ci.yml`이 테스트와 빌드를 돌립니다.
