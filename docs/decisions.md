### 프로필 구축 (시안 02)

- 10화면을 "프로필 구축 n/5" 마법사(`/profile/build/*`)로 만들었습니다. 분류는 복수 선택이고, 고른 순서대로 인터뷰 → 카드 생성을 반복한 뒤 추가 → 종합 분석 → 미리보기(전체/활동/아르바이트/자격증·교육 탭) → 활용 안내 → 완료로 이어집니다. 진행 상태는 `localStorage`(`khu-build`)에 둡니다.
- 종합 분석은 LLM(`/api/analyze-profile`, 강점 3~5개 제목+근거)으로 바꿨고, 코드로 세던 역량 빈도는 보조 칩으로 남겼습니다. 결과는 `Profile.strengths`(제목)와 `strengthDetails`(제목+근거)에 저장합니다.
- 경험 인터뷰 대본의 예시 나열은 "- " 대신 "·"로 씁니다. "- "는 앱이 선택 칩으로 해석하기 때문입니다.

### 자소서 (시안 03)

- `/essay`는 쿠키와의 자유 대화 화면이고, 시안의 칩 4개는 보내는 대신 화면을 여는 `quickActions`로 만들었습니다(지원 건 추가·공고 링크·직무 탐색·지원 건 목록). 입력창은 자소서 챗봇(`CHATKHU_BOT_ESSAY`, 대체 지시문 `essay-chat.ts`)과 대화합니다.
- 지원 건 추가는 입력 → 분석 → "채용공고 요약 / 핵심 키워드 / 자소서 문항" 탭 화면 → "이 공고로 자소서 작성하기" 순서이고, 저장하면 첫 문항 화면으로 바로 갑니다. 공고 분석 출력에 `summary`를 추가했습니다.
- 문항 화면은 3단계입니다. 경험 매칭(추천 경험은 공고 키워드·문항과 카드의 역량·활동이 겹치는 정도로 코드가 순서를 매김, 추가 탐색, 새로 찾기) → 초안(AI 초안·키워드 강조·다른 버전 탭) → 첨삭(전체 피드백·문장 개선·표현 제안 탭, Before/After). "전체 문장 수정하기"는 `/api/essay-draft`의 `revise` 모드로 새 버전을 만듭니다.
- 경험 세부 내용 확인·보완(시안 4·5번)은 카드를 누르면 뜨는 시트로 만들었습니다. 쿠키의 추가 질문(카드의 `missing` 첫 항목)에 답하면 카드의 주요 활동에 덧붙이고, 핵심 포인트 요약을 보여 줍니다.
- 지원 건 상세는 "문항별 보기 / 전체 보기" 탭과 지원 현황 타임라인(자소서 작성 완료 → 서류 제출 → 면접 준비)을 보여 주고, 모든 문항이 완료되면 "이 자소서로 제출하기"가 단계를 "제출"로 바꾸고 다음 단계 화면(시안 10번, 칩 4개)으로 갑니다. 단계를 "최종"으로 바꾸면 합격 엔딩(`/celebrate/:appId`)을 열 수 있습니다.
- 자소서 첨삭 출력에 `points`(피드백 항목)와 `examples`(Before/After)를 추가했습니다.

### 면접 (시안 04)

- 시작 화면은 4갈래(지원 기업·직무 유형·자소서 기반·자유)이고, 설정 화면은 회사 카드(변경하기 시트), 면접 유형 4개, 연습 방향 칩, "내 자소서 기반 맞춤 질문" 토글입니다. 설정은 `localStorage`(`khu-mock-setup`)에 둡니다.
- 세션은 공용 ChatShell 대신 전용 화면입니다. 정장 캐릭터 위에 질문 카드가 뜨고, 마이크로 녹음(MediaRecorder, 파형, 60초 타이머)한 뒤 wav 16kHz 모노로 바꿔 `/api/stt`로 받아씁니다. 키가 없으면 체험 대본 답변이 "받아쓴 것처럼" 옵니다. 마이크가 없거나 거부되면 "글로 답하기"로 바뀝니다. 질문은 `/api/tts`로 읽어 주고, 서버 TTS가 없으면 브라우저 음성 합성을 씁니다. 음성 녹음(6단계)을 틀만 먼저 만든 것이며, ChatKHU STT·TTS 본문 형식은 실측 전입니다.
- 첫 질문 "Q1. 자기소개를 해주세요."는 앱이 고정으로 내고, 면접관 지시문은 Q1-1(꼬리) → Q2(회사·직무) → Q3(상황·압박) → Q4(목표) 순서와 번호 표기 규칙을 가집니다. 5번째 답 뒤에는 이벤트가 없어도 자동으로 채점합니다.
- 채점 항목 이름을 시안대로 논리력·직무 이해도·경험 구체성·소통력으로 바꿨고, 출력에 `perQuestion`(문항별 점수·좋았던 점·개선점·추천 답변 방향·모범 답안)을 추가했습니다. 결과 화면은 요약(점수 원, 4항목, 전반적인 평가)과 상세(종합 피드백·문항별 분석·모범 답안 예시 탭)로 나눴습니다.
- 음성 세션의 받아쓰기 크레딧은 파일 크기로 근사합니다(실측 뒤 교정).

## 2026-10-23 (1차 자체 점검)

키와 캐릭터 이미지가 오기 전에 배포된 사이트를 폰 폭(375px)으로 모듈 4개 끝까지 돌려 보고, 눈에 띄는 것부터 고쳤습니다. 가로 넘침, 이름 없는 버튼, 콘솔 오류는 없었습니다.

- 경험 인터뷰 체험 대본을 분류별(9종)로 나눴습니다(`server/demo/interview.json`의 `byCategory`, 고르는 코드는 `src/lib/demoScript.ts`). 전에는 어떤 분류를 골라도 "경영컨설팅 학회 학술부" 카드가 나와서 프로필 미리보기와 자소서 경험 매칭에 같은 카드가 두 번 보였습니다. 브라우저와 서버가 같은 함수로 대본을 고르고, 분류는 ChatShell 의 화면 문맥 문장에서 읽습니다.
- 모듈 4개(직무 탐색, 프로필, 자소서, 면접)를 `React.lazy`로 나눠 받습니다(`src/screens/*/index.ts` 묶음). node_modules 는 `vendor` 한 덩어리입니다. 첫 로딩 JS가 562KB 한 덩어리에서 앱 37KB + vendor 352KB(배포마다 안 바뀜)로 줄었고, 모듈은 30KB 안팎씩 그 탭에 갈 때 받습니다. 첫 화면이 뜬 뒤 한가할 때 네 묶음을 미리 받아 두므로 탭 전환은 끊기지 않습니다.
- 링크 공유 미리보기(og:title·description·image·url)와 iOS 홈 화면 추가 메타를 `index.html`에 넣었습니다. 절대 주소는 `VITE_SITE_URL`(기본값 Pages 주소, `vite.config.ts`)로 채웁니다. 이미지는 지금 앱 아이콘이고 캐릭터가 오면 바꿉니다. 매니페스트 `lang`을 `ko`로 지정했습니다.
- 본문에 `word-break: keep-all`을 적용해 한국어가 어절 중간에서 끊기지 않게 했습니다. 띄어쓰기 없는 긴 글자는 `overflow-wrap: anywhere`로 넘치지 않게 끊습니다.
- 채팅 입력창을 한 줄 `input`에서 6줄까지 늘어나는 `textarea`로 바꿨습니다. Enter 는 보내기, Shift+Enter 는 줄바꿈이고, 한글 조합 중 Enter 는 보내지 않습니다.
- 문구: 프로필에 저장된 직무가 없으면 "다시 탐색" 대신 "탐색하기", 프로필 구축 헤더는 "프로필 구축 n/5" 칩 하나, 면접 설정 안내문의 마이크 아이콘을 첫 줄에 맞췄습니다.
